## 1. 背景与概述

### 1.1 为什么要有固定评定标准

行情做市不是「挂得上就行」。对外盘口是用户下单的第一触点，对内账是配资与对冲的第一本账。没有统一尺子会出现三类问题：

- **盘口不可比**：同一交易对今天 0.5 bp、明天 8 bp，客诉「滑点大」无法判定是策略退化还是市场波动。
- **K 线不对标**：本所 1 分钟 K 的 high / low / close 相对主流所漂移过大，用户看到的走势与 Binance 不是同一市场，套利与做市会互相伤害。
- **盈亏算不清**：代币涨跌、未实现盈亏、手续费混在一起，看不出做市本身赚没赚钱。

本文件把「盘口差、深度、K 线对标、铺单颗粒度、现货对冲、库存偏移、合约快照盈亏」七项收成**同一套快照协议**。值班、调参、复盘都按这套口径，不另开口头标准。

### 1.2 范围

| 类别 | 在范围内 | 不在范围内 |
|---|---|---|
| 盘口质量 | 买卖一价差、近端深度阶梯、价位缝隙 | 撮合引擎内部排队、延迟 SLA |
| 行情对标 | 1 分钟 K 的 high / low / close / volume 相对对标所 | 日 K / 周 K、指标线（MA/BOLL）形态审美 |
| 账务与风控 | 初始配资、代币库存偏移、USDT 增减、合约 UPNL + 手续费 | 公司级财务报表、税务口径 |
| 采样 | UTC 日 300 次随机快照、按交易对独立打分 | 逐笔成交实时评分（二期） |
| 交易对 | 以 BTC/USDT、ETH/USDT 为 L1 样板，其余按分级表 | 未上架、停牌、无对标所的交易对 |

### 1.3 一句话口径

> 每个交易对、每次快照，先过**风控硬闸**（盘口差、近端深度、库存偏移），再记**做市质量分**（深度阶梯、K 线对标、颗粒度、快照盈亏）。一天 300 次，合格率决定当日绩效档。

## 2. 目标与原则

### 2.1 业务目标

- **盘口可成交**：L1（BTC/ETH）买卖价差压在万一以内，1% 偏离内累计深度达到 500 万 U。
- **走势可对标**：本所 1 分钟 K 与 Binance 同分钟的 high / low / close 偏差不超过万五，成交量至少为对标所的 50%。
- **铺单无空洞**：近端价位按 tick 铺满，不允许「看起来有深度、点进去全是跳空」。
- **对冲可解释**：代币数量盯住目标库存，盈亏只从 USDT（及合约 UPNL、手续费）上体现。
- **绩效可复盘**：任意一天都能回答「300 次里过了多少、卡在哪一项」。

### 2.2 技术目标

| 指标 | 目标值 |
|---|---|
| 日快照次数 | 300 / 交易对 / UTC 日（缺失须记原因，不静默少采） |
| 小时内分布 | 每小时约 12～13 次，时刻在小时内均匀随机 |
| 单次快照计算 | 本所盘口 + 对标所盘口 / 1m K 对齐同一 `snapshot_at` |
| 金额 | 深度名义、盈亏一律 decimal，禁止二进制浮点累加 |
| 时间 | `snapshot_at` UTC，K 线桶按交易所官方 1m 开收时间对齐 |

### 2.3 设计原则

1. **交易对分级，禁止一套阈值打天下**。BTC/ETH 是样板，山寨放宽，但必须写在配置里，不能口头放宽。
2. **风控硬闸 ≠ 质量打分**。价差炸了、1% 深度不够、库存飞出带宽，该次快照直接不合格，不靠别的项「平均回来」。
3. **随机快照，避免整点博弈**。固定 `:00` / `:30` 采样会被策略对准；小时内随机打散。
4. **对标所是行情锚，不是利润锚**。K 线要对齐主流平台；盈亏仍按本所账 + 对冲账算。
5. **代币数量不是利润**。BTC/ETH 库存视为配资工具，涨跌不计入做市绩效；只看 USDT 增减、合约未实现盈亏和手续费。
6. **同一快照、同一时刻**。盘口差、深度、颗粒度必须来自同一次 orderbook；K 线用该分钟已收盘的 1m（未收盘的当前分钟不参与第 3 项）。

## 3. 规范定义

### 3.1 术语

| 术语 | 定义 |
|---|---|
| 本所 | 正在做市、被评定的交易场所 |
| 对标所 | 默认 Binance；交易对可覆盖为 OKX / Bybit |
| `mid` | `(ask1 + bid1) / 2`，本所最优买卖中点。无盘口时该次快照记 `NO_BOOK`，不打分 |
| 盘口差 / spread | `(ask1 - bid1) / mid`，下文用 **bp（万分之一）** 表示：`spread_bp = spread × 10000` |
| 偏离带宽 | 相对 `mid` 的百分比，如 1% 指 `[mid×0.99, mid×1.01]` |
| 累计深度 | 某偏离带宽内，买盘或卖盘（或双侧，见指标定义）挂单名义价值之和，单位 USDT |
| 价位 / tick | 本所 `price_precision` 对应的最小价格步长 |
| 缝隙 | 近端应挂的 tick 上没有任何有效挂单 |
| 目标库存 | 初始配资确定的代币数量（BTC/ETH 等），评定期间视为常数 |
| 偏移度 | `(current_qty - target_qty) / target_qty` |
| 买盘资产 USDT | 用于买币的稳定币余额（现货可用 + 冻结按配置计或不计，见 §6.5） |
| UPNL | 合约未实现盈亏，按该快照标记价计算 |
| 快照合格 | 该次所有硬闸通过，且质量项全部达到该项阈值 |
| 日合格率 | `合格快照数 / 有效快照数`。对标所宕机等记入「无效快照」，不进分母 |
| 对标价 | 聚合主流所盘口得到的加权参考价；挂单、分层、撤补单的基准（见 §4） |
| 近盘 / 中盘 / 远盘 | 相对对标价的深度带：默认 0%～1% / 1%～3% / 3%～10%，挂单占比可配 |
| 网格挡 | 单侧买卖盘上的一档独立挂单元（默认 10 挡），各有价格/数量区间与动态规则 |

### 3.2 单位与符号

| 符号 | 含义 | 单位 |
|---|---|---|
| `spread_bp` | 相对价差 | bp，1 bp = 0.01% = 万分之一 |
| `depth_notional_usdt(δ)` | 相对 mid 偏离 `δ` 内的累计名义 | USDT，decimal |
| `k_dev_bp` | 本所 K 与对标所 K 的相对偏差 | bp |
| `vol_ratio` | 本所 1m 成交量 / 对标所同分钟成交量 | 无量纲 |
| `fill_ratio` | 近端应挂 tick 中实际有单的比例 | 0～1 |
| `offset_ratio` | 代币库存相对目标的偏移 | 有符号比例 |
| `snapshot_pnl_usdt` | 相对上一快照（或日初）的做市盈亏 | USDT |

百分数口头习惯对照：

| 口头 | 比例 | bp |
|---|---|---|
| 万一 | 0.01% | 1 |
| 万五 | 0.05% | 5 |
| 1% | 1% | 100 |

### 3.3 指标角色（风控 vs 做市质量）

| 编号 | 指标 | 角色 | 不过会怎样 |
|---|---|---|---|
| M1 | 盘口差 | **风控硬闸** | 用户吃单滑点、对外报价失真 |
| M2 | 近端深度（含递增阶梯） | **硬闸（1% 门槛）+ 质量（阶梯）** | 大单砸穿、盘口「看起来厚实际空」 |
| M3 | 1m K 对标 | **做市质量** | 走势与主流所脱锚，套利单向收割 |
| M4 | 铺单颗粒度 / 缝隙 | **做市质量** | 中间跳空，市价单直接穿越数档 |
| M5 | 现货对冲盈亏（USDT） | **做市质量（账）** | 看不出做市本身赚不赚钱 |
| M6 | 库存偏移 | **风控硬闸** | 变成单边持仓，配资风险失控 |
| M7 | 合约快照盈亏（UPNL + 费） | **做市质量（账）** | 现货看起来赚钱、合约把利润吃掉 |

硬闸失败 → 该次快照 **不合格**，质量分仍记录，便于复盘，但不参与「用质量分把硬闸拉回来」。

## 4. 铺单策略（动态深度网格）

本节写**怎么挂**；§6 起写**怎么评**。策略产出的盘口必须能过 M1～M4 硬闸与质量项，否则只是「挂上了」不算做市合格。

### 4.1 获取对标价（参考价格）

聚合主流交易平台（默认 Binance、OKX、Bybit、Gate、MEXC）当前盘口，计算**加权平均价**作为对标价。

| 项 | 说明 |
|---|---|
| 加权方式 | 按成交量、挂单量、报价优先级等自定义；权重写在交易对配置里，禁止口头改 |
| 用途 | 挂单逻辑、深度划分、撤单判断的基准价 |
| 与 `mid` 的关系 | `mid` 是本所盘口中点（评定用）；对标价是外所锚。两者偏离过大时，策略应先纠偏再谈铺单密度 |

金额与价格一律 decimal；时间戳用 UTC。

### 4.2 深度分层（近盘 / 中盘 / 远盘）

将挂单深度划分为三个区域，每个区域配置不同的挂单占比与策略规则：

| 区域 | 深度范围（相对对标价） | 默认挂单占比 | 描述 |
|---|---|---|---|
| 近盘 | 0% ～ 1% | 10% | 靠近对标价，快速成交，优先流动性引导 |
| 中盘 | 1% ～ 3% | 40% | 主要挂单密度，分层引导交易深度 |
| 远盘 | 3% ～ 10% | 50% | 防守型挂单，缓冲大单冲击、预留风险 |

各区域的价格范围与挂单占比可按交易对市值、流动性等级、波动性调整。配置变更须落盘，并与 §6.2 M2 深度阶梯、§6.4 M4 颗粒度对齐：近盘薄、远端堆一坨会过不了递增检测与缝隙检查。

### 4.3 网格化铺单（单侧 10 挡）

每个盘口方向（买 / 卖）设置 **10 挡**挂单深度。每一挡是一个**独立网格单元**，带自己的策略控制参数。

#### 每挡控制参数

| 参数 | 含义 |
|---|---|
| 挂单价格范围 | 相对对标价 ±X%，是否落在该挡可接受区间 |
| 挂单数量范围 | 该挡挂单量须在预设区间（如 `0.01`～`1` BTC，decimal） |
| 动态规则触发 | 见下表；触发后撤单、缩区或进入冷却，禁止无脑补单 |

#### 动态规则（触发 → 动作）

| 触发 | 动作 |
|---|---|
| 当前盘口价超出该挡设定阈值 | 自动撤单 |
| 对冲风险暴露加剧 | 取消远盘 / 中盘，保近盘与库存带宽 |
| 成交过快 | 进入冷却期，暂不补单 |
| 用户主动单穿透该挡 | 临时撤销或调价 |

- **满足网格规则**：继续保留并维护该档挂单。
- **不满足规则**：自动撤单，或调整价格 / 数量后再挂。

### 4.4 其它约束

- 网格**不是**等价间距：可按市值、波动性、历史深度做动态分布；近端密、远端疏，与 M4「近端密铺」一致。
- **回补机制**：某一挡成交后，仅在价格区间、数量区间、冷却与库存带宽均满足时补回。
- **状态缓存 + 标记**：每挡维护状态（在挂 / 冷却 / 已撤 / 待补），避免频繁撤挂抬高手续费与拒单率。
- 改 `price_float` / `price_precision` 前，先算万一带宽内还能不能铺满目标 tick（见 §6.4、§12）。

## 5. 核心评定流程

```
UTC 小时开始
  → 在该小时内抽取 12～13 个随机时刻（全日合计 300）
  → 到达时刻拉齐：本所 orderbook + 对标所 orderbook + 上一根已收盘 1m K
  → 按交易对配置计算 M1～M7
  → 硬闸（M1、M2 的 1% 门槛、M6）全过？
        否 → snapshot_pass = false
        是 → 质量项（M2 阶梯、M3、M4、M5/M7 当日账）全过？
              否 → snapshot_pass = false
              是 → snapshot_pass = true
  → 写入快照记录（配置阈值快照一并落盘，避免事后改配置改写历史）

UTC 日终
  → 有效快照数 = 300 - 无效快照（对标所宕机、本所维护、无盘口）
  → pass_rate = 合格数 / 有效快照数
  → ≥ 0.95 → A+；≥ 0.80 → B+；其余按 §9 档位
```

一次快照内部顺序固定为：先盘口（M1/M2/M4），再已收盘 K 线（M3），再账（M5/M6/M7）。K 线未收盘不拿「当前分钟」去比 high/low/close。

## 6. 指标体系

以下 BTC/ETH 数字是 **L1 样板**。其他交易对用 §7 的分级表覆盖，公式不变。

### 6.1 M1 盘口差（每小时随机快照）

**测什么**：最优卖价与最优买价相对中点的宽度。

```
mid        = (ask1 + bid1) / 2
spread_bp  = (ask1 - bid1) / mid × 10000
pass       = spread_bp ≤ spread_bp_max
```

| 交易对级别 | `spread_bp_max` | 含义 |
|---|---|---|
| L1 BTC / ETH | **1** | 万一以内 |
| L2 主流（如 SOL、XRP） | 3 | 可配置 |
| L3 长尾 | 10 | 可配置 |

**附加约束（风控）**：

- `ask1 > bid1`，否则记交叉盘口 `BOOK_CROSS`，硬闸失败。
- 单侧缺档（无 bid 或无 ask）→ `BOOK_ONE_SIDE`，硬闸失败。
- 用本所盘口算差，不和对标所价差做差；对标所只用于 M3。

**复杂度**：单次 O(1)。

---

### 6.2 M2 深度（与 M1 同一快照，可递增检测）

**测什么**：离开 mid 不远的地方，有没有足够的 USDT 名义接住冲击。

记买盘价格从高到低为 `bid_i`，卖盘从低到高为 `ask_i`，数量为标的张/币，价格为 USDT。名义一律 decimal：

```
bid_notional(δ) = Σ  bid_i × qty_i    其中  bid_i ≥ mid × (1 - δ)
ask_notional(δ) = Σ  ask_i × qty_i    其中  ask_i ≤ mid × (1 + δ)
```

**硬闸（用户给定的底线）**：BTC/ETH 在 **1%** 偏离内，买卖**各自**达到 500 万 U：

```
δ = 0.01
pass_gate = bid_notional(0.01) ≥ 5_000_000
         AND ask_notional(0.01) ≥ 5_000_000
```

双侧都要满足：只堆一侧不算过。500 万是 L1 的 1% 档门槛，不是「买卖加总 500 万」。

**递增检测（质量，推荐默认阶梯）**：同一份 orderbook 上再切更近的带宽。近端先过，再看远端，避免「1% 处堆一坨、盘口附近是空的」。

L1（BTC/ETH）默认阶梯（可按交易对改）：

| 偏离 `δ` | 单侧累计名义 ≥ | 说明 |
|---|---|---|
| 0.10% | 80 万 U | 盘口附近就能接住中等单 |
| 0.20% | 150 万 U | |
| 0.50% | 300 万 U | |
| **1.00%** | **500 万 U** | **硬闸** |

阶梯必须单调：更宽的带宽门槛不得低于更窄的（配置校验，启动时拒绝乱序配置）。

**递增判定**：

- 硬闸只看 1% 档。
- 质量项：所有已配置阶梯全部达标才算 M2 质量通过。
- 复盘时保留每档实际名义，便于看是「近端空」还是「远端不够」。

**复杂度**：对档位数 n，单次 O(n)；阶梯段数固定为常数。

### 6.3 M3 分钟 K 线对标与走势

**测什么**：本所刚收盘的 1 分钟 K，是否跟主流所是同一根市场。

对齐规则：

- 取 **上一根已收盘** 的 1m，开盘时间相同（UTC 对齐到分钟）。
- 比较 `high` / `low` / `close`（用户指定这三项；`open` 作为走势辅助，不单独卡万五）。
- 成交量比的是**同分钟、同计价口径**的成交量。本所若以张计，先换成标的数量或 USDT 名义，再和对标所比；配置里写明 `volume_unit`。

相对偏差（对标所该字段为 0 时见 §11）：

```
k_dev_bp(field) = |local.field - bench.field| / bench.field × 10000
field ∈ {high, low, close}
```

L1 阈值：

| 检查 | 通过条件 |
|---|---|
| 价格区间 | `k_dev_bp(high) ≤ 5` 且 `k_dev_bp(low) ≤ 5` 且 `k_dev_bp(close) ≤ 5` |
| 成交量 | `vol_ratio = local_volume / bench_volume ≥ 0.50` |
| 走势 | `sign(local.close - local.open) == sign(bench.close - bench.open)`；任一侧 `|close-open|/open < 1 bp` 视为十字星，**不判走势** |

「区间偏差不能超过万五」指 high、low、close **每一项**相对对标所同字段，不是把 high-low 振幅拿去比。振幅本身可以和对标所不同，但高低点不能漂出万五。

**量能下限取 50% 的原因**：做市所流动性通常弱于 Binance，不要求放量对齐，但低于一半说明本所这一分钟几乎没有真实成交或铺单完全没接到量，盘口质量数字会失真。

**不做的事**：不比 MA、不比形态「好不好看」。只比同一分钟的价格锚和量能地板。

---

### 6.4 M4 铺单颗粒度（价格缝隙）

**测什么**：近端深度是「密铺」还是「几档撑场面」。

用户口径：深度万一以内，应有约 **100 个价位**，且都要填上。

落地定义（L1）：

```
band        = mid × 0.0001          // 万一
tick        = 10^(-price_precision)
expected_n  = floor(band / tick)    // BTC 在 round number 上常接近 100
bid_ticks   = 从 bid1 向下、落在 [mid - band, mid] 内的应有 tick 集合
ask_ticks   = 从 ask1 向上、落在 [mid, mid + band] 内的应有 tick 集合
fill_ratio  = 实际有有效挂单的 tick 数 / expected_n     （买卖分别算，再取较差侧）
gap_count   = 连续空 tick 的最长段
```

通过条件（L1 默认）：

| 项 | 阈值 |
|---|---|
| `expected_n` | 配置目标 100；若 `tick` 导致期望不是 100，以 `floor(band/tick)` 为准，不硬改价格精度 |
| `fill_ratio` | ≥ 1.00（满铺）；值班可把告警线放在 0.98，但 **A+ 仍要求 1.00** |
| `gap_count` | = 0（不允许连续空档） |
| 单档数量 | 有价无量（量为 0）视为未填 |

与 M2 的分工：M2 问「钱够不够」，M4 问「档密不密」。1% 里堆满 500 万但集中在 3 个价位，M2 能过、M4 不过。

**复杂度**：近端 tick 约 100，单次 O(expected_n)。

---

### 6.5 M5 现货对冲评定（USDT 增减）

**测什么**：在「代币数量保持目标值」的前提下，做市有没有从价差里赚到稳定币。

会计恒等式（现货侧）：

```
日初：  target_qty 份代币 + usdt_equity_0
快照 t： current_qty 份代币 + usdt_equity_t

约定：代币数量不参与盈亏（涨跌归库存，不归做市绩效）
spot_pnl_usdt_t = usdt_equity_t - usdt_equity_0
```

`usdt_equity` 建议口径（必须在配置里写死，禁止同一天换口径）：

| 计入 | 不计入 |
|---|---|
| 现货 USDT 可用余额 | 代币市值（BTC/ETH 按价折 U） |
| 现货 USDT 挂单冻结（买盘占用） | 未对冲的山寨库存市值 |
| | 借贷利息（单独科目，二期） |

「只算买盘资产 USDT 的增减」：买盘挂出会冻结 USDT，这部分仍是做市占用的稳定币，**算进权益**，否则一挂单账面 USDT 下降会被误判为亏损。

每个快照记录 `spot_pnl_usdt`，日终看：

```
pass_m5 = spot_pnl_usdt_eod ≥ pnl_floor_usdt
```

L1 默认 `pnl_floor_usdt = 0`（日终不亏）。更严的档位可改为「覆盖当日手续费后仍 ≥ 0」，与 M7 合并看 §6.7。

M5 **不是**硬闸：单次快照亏损不直接打挂该次（对冲有时滞）；但 **M6 库存飞出带宽是硬闸**。日终 M5 不过 → 当日质量项失败，影响能否拿 A+/B+（见 §9：日终账记入「日级质量闸」，与快照合格率同时生效）。

---

### 6.6 M6 库存偏移（超出必须买回或卖出）

**测什么**：代币有没有漂成单边方向性仓位。

```
offset_ratio = (current_qty - target_qty) / target_qty
pass_m6      = |offset_ratio| ≤ offset_ratio_max
```

| 级别 | `offset_ratio_max` | 处置 |
|---|---|---|
| L1 BTC / ETH | **2%**（推荐默认，可配置） | 超上限 → 卖出代币（或合约加空）；超下限 → 买回 |
| L2 / L3 | 3% / 5% | 同左 |

`target_qty` 来自初始配资，评定周期内视为常数。配资调整必须换新的 `allocation_id` 并重置日初权益，禁止悄悄改目标库存来「做平」历史偏移。

快照发现越界：

1. 该次硬闸失败。
2. 策略侧必须在配置的 `rebalance_timeout`（建议 60s）内把库存拉回带宽。
3. 超时未拉回 → 升级告警，后续快照连续失败，直到回到带宽。

---

### 6.7 M7 合约快照盈亏（未实现 + 手续费）

**测什么**：对冲若走永续 / 交割，不能只看现货 USDT；要把合约浮盈浮亏和费加回来，才是做市真实结果。

```
futures_upnl_t     = 按 snapshot 标记价计算的未实现盈亏（decimal）
fee_amount_t       = 自日初累计手续费（吃单/挂单，取绝对值累加）
funding_amount_t   = 自日初累计资金费（付出为正费用，收取为负费用）

hedge_pnl_usdt_t   = spot_pnl_usdt_t + futures_upnl_t - fee_amount_t - funding_amount_t
```

说明：

- `spot_pnl_usdt` 仍按 M5：代币数量不当利润。
- `futures_upnl` 必须进快照：否则现货卖出代币换 U「账面大赚」、合约空单浮亏被藏住。
- 手续费、资金费进入同一条快照盈亏，避免「毛利很好、净利是负」。
- 合约仓位的**标的数量**应与现货库存偏移对冲：`spot_qty + futures_qty ≈ target_qty`（符号按多空约定）。对冲缺口超过 `hedge_gap_ratio_max`（建议 1%）时记 `HEDGE_GAP`，该次质量失败。

日终：

```
pass_m7 = hedge_pnl_usdt_eod ≥ pnl_floor_usdt
```

与 M5 同时开启时，**以 M7 为准**（M7 已包含现货 USDT 增减）。M5 仍落盘，用于拆开「现货腿 vs 合约腿」。

## 7. 交易对分级与阈值

每个交易对必须能落到下表某一档，并允许单币覆盖。未配置的交易对 **禁止上线做市评定**（缺配置 ≠ 沿用 BTC）。

| 级别 | 典型交易对 | M1 价差 | M2 1% 单侧深度 | M2 是否递增 | M3 价格偏差 | M3 量能 | M4 近端 tick | M6 偏移 |
|---|---|---|---|---|---|---|---|---|
| L1 | BTC/USDT、ETH/USDT | ≤ **1 bp** | ≥ **500 万 U** | 是 | ≤ **5 bp** | ≥ **50%** | 万一内满铺（约 100 档） | ≤ 2% |
| L2 | 主流山寨 | ≤ 3 bp | ≥ 100 万 U | 是 | ≤ 10 bp | ≥ 30% | 近端满铺，档数按 tick | ≤ 3% |
| L3 | 长尾 | ≤ 10 bp | ≥ 20 万 U | 可选 | ≤ 20 bp | ≥ 20% | 允许 2% 空档率 | ≤ 5% |

L1 是本文件的强制样板，改 L1 数字视为修订本规范，需要评审，不能只改配置文件蒙混。

## 8. 快照采样

### 8.1 密度

- 每个交易对、每个 UTC 自然日目标 **300** 次。
- 24 小时均匀：每小时 12 次，另 12 次撒在随机小时作为补齐（300 - 24×12 = 12），或每小时 12～13 次（12×18 + 13×6 = 300）。实现任选一种，但必须在日开始前抽好时刻表，禁止「忙的时候少采」。
- 小时内时刻 **均匀随机**，最小间隔建议 ≥ 20s，避免连打同一根盘口。

### 8.2 对齐

同一 `snapshot_id` 内：

| 数据 | 对齐方式 |
|---|---|
| 本所 orderbook | 快照时刻最近一份，延迟超过 `book_stale_ms`（建议 1500ms）则无效 |
| 对标所 orderbook | 仅用于辅助诊断，不参与 M1/M2 硬闸 |
| 1m K | 上一根已收盘；本所与对标所 `open_time` 必须相同 |

### 8.3 有效 vs 无效

| 情况 | 记法 | 是否进合格率分母 |
|---|---|---|
| 正常算出 M1～M7 | 有效 | 是 |
| 对标所 REST/WS 超时 | `BENCH_DOWN` | 否 |
| 本所维护 / 无盘口 | `LOCAL_DOWN` | 否 |
| 本所有盘口但对标 K 缺失 | M1/M2/M4/M6 仍评；M3 记无效 | M3 不拖累快照时：该快照「部分有效」，**硬闸仍算**；M3 从日质量闸单独扣（见 §9） |
| 随机时刻撞上分钟收盘边界 | 等 2s 再取已收盘 K；仍没有则 M3 无效 | 同上 |

无效快照必须留原因码。无效过多（有效快照 < 240，即一天 80% 都采不到）→ 当日绩效记 `INSUFFICIENT_SAMPLE`，**不发 A+/B+**。

## 9. 日绩效分级

### 9.1 快照合格

一次有效快照 `snapshot_pass = true` 当且仅当：

1. M1 通过  
2. M2 硬闸（1% 深度）通过  
3. M4 通过  
4. M6 通过  
5. M3 若该次有效，则通过；若该次 M3 无效，不挡 `snapshot_pass`（改由日级质量闸处理）

M5/M7 按 **日终** 结算，不在单次快照上卡「这一秒必须赚钱」。

### 9.2 日合格率

```
pass_rate = count(snapshot_pass) / count(valid_snapshot)
```

| 日合格率 | 快照档 |
|---|---|
| ≥ **95%** | 快照 **A+** |
| ≥ **80%** 且 < 95% | 快照 **B+** |
| ≥ 60% 且 < 80% | C |
| < 60% | D |

用户给定的运营口径：**能稳在 80% 视为绩效 B+，能稳在 95% 视为绩效 A+**。C/D 用于内部退化告警，不作为对外承诺档。

### 9.3 日级质量闸（账 + K 线覆盖）

快照档拿到 A+ / B+ 之后，还要过日级闸才算当日最终绩效：

| 闸 | 不过的后果 |
|---|---|
| M7（无合约则 M5）日终 `hedge_pnl_usdt ≥ pnl_floor` | 最终绩效降一档（A+→B+，B+→C） |
| 当日有效 M3 次数 ≥ 有效快照的 80%，且有效 M3 通过率 ≥ 快照档对应门槛（A+ 要 95%，B+ 要 80%） | 最终绩效降一档 |
| 有效快照 < 240 | 直接 `INSUFFICIENT_SAMPLE`，无 A+/B+ |

最终绩效 = 快照档 再 过日级闸。对外只公布最终绩效。

### 9.4 连续日

建议另记 7 日滚动合格率，但不替代「当日 300 次」这根尺子。滚动指标用于看策略是否在退化，不在本文件改档位。

## 10. 风控处置

评定是尺子，处置是动作。快照失败必须能映射到人可执行的步骤。

| 触发 | 级别 | 动作 |
|---|---|---|
| M1 超阈 | P1 | 检查铺单盒子近端是否空、是否交叉；必要时暂停吃单、只挂撤 |
| M2 1% 深度不足 | P1 | 加近端量或缩减对外市价单限额；递增档近端失败优先补盘口 |
| M3 连续 N 根（建议 5）价格偏差超万五 | P1 | 核对指数/标记价源、是否错对标所、本所成交是否被操纵 |
| M3 量能持续 < 50% | P2 | 查成交是否真实、手续费与 maker 比例 |
| M4 出现缝隙 | P2 | 对 depth-gather / 铺单盒子查缺档层；补 tick 或收紧 `price_float` |
| M6 超出偏移带宽 | **P0** | 立即买回或卖出（现货）或调合约仓，使库存回到带宽；超时升级 |
| M7 日终亏超 `pnl_floor` | P1 | 拆现货腿 / 合约腿 / 手续费 / 资金费四笔，禁止只看现货 USDT |
| `HEDGE_GAP` | P0 | 对冲腿数量与现货库存对齐 |

P0 允许打断自动做市循环；P1 告警 + 值班处理；P2 记入次日调参。

## 11. 边界与异常

| 场景 | 处理 |
|---|---|
| 对标所该分钟成交量为 0 | `vol_ratio` 不判；M3 价格项仍判。连续 3 根对标量为 0 → M3 整项无效 |
| 对标所 high/low/close 为 0 或负 | 该次 M3 无效，记 `BENCH_K_INVALID` |
| 本所停牌 / 集合竞价 | 该段快照 `LOCAL_AUCTION`，无效 |
| 价格精度变更导致万一内 tick ≠ 100 | M4 按新 `expected_n` 评，不要求数字永远等于 100 |
| 配资调增/调减 | 新 `allocation_id`，当日剩余快照用新 `target_qty` 与新的 USDT 日初（从调配时刻切开两段日） |
| 合约结算、资金费结算落在快照之间 | 计入最近一次 M7 的累计项，不回溯改已写快照 |
| 本所与对标所 1m 开盘差 1s 以上的时钟 | 以本所交易所时间为准平移对标 K；无法对齐则 M3 无效 |
| 深度档位未按价格排序 | 计算前必须排序；乱序配置视为实现错误，快照失败 `BOOK_UNSORTED` |

金额与时间（与团队铁律对齐）：

- 深度名义、盈亏、手续费：**decimal**，禁止 `float64` 累加后再「四舍五入救回来」。
- `snapshot_at`、K 线 `open_time`：**UTC**，对外 ISO 8601。禁止存「交易所本地小时」字符串当主键。

## 12. 与本仓库工具的对应

本规范是尺子；`quant-visual-tools` 里的页面是看盘与铺单的眼睛。对应关系如下，便于值班按图找原因。铺单怎么挂见 §4；下面只写「评不过时优先看哪」。

| 指标 | 优先看的工具 | 看什么 |
|---|---|---|
| M1 盘口差 | [depth-chat](../depth-chat/depth-chat.html) 顶栏 AP/BP/Cap；[铺单页](../market-making/index.html) 盘口行 | Cap 是否持续大于 1 bp；是否买卖重叠 |
| M2 深度 | depth-chat 深度对比；[depth-compare](../depth-compare/depthCompare-chat.html) | 1% 内累计名义；近端是否空、远端是否堆；是否符合 §4.2 近/中/远占比 |
| M3 K 线 | depth-chat K 线；独立仓库 [trade-backtest](https://github.com/kary2999/trade-backtest) | 同分钟 high/low/close 是否贴 Binance |
| M4 缝隙 | [depth-gather](../depth-gather/README.md)（均匀性） | 相邻价档是否缺档、Qty 是否断崖；10 挡网格是否漏铺 |
| M5/M6/M7 | 账务与仓位不在本静态站内计算；本规范只定口径 | 库存、USDT、UPNL、手续费按 §6.5～6.7 |

铺单盒子的 `price_float` / `price_precision` 直接决定 M4 的 `expected_n`。改盒子前先算：万一带宽里还能不能铺满目标 tick，再改精度。策略侧改近/中/远占比或 10 挡规则时，同步核对 M2 阶梯与 M4 满铺是否仍可达成。
