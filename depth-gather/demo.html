depthGather-chat · 深度均匀性查看

主要目的：查看本所某交易对挂单深度是否均匀（各档 Qty 是否合理、有无断崖/缺档）。 产品说明见 README.md（封板文档）。 下文为 Mock / 接口技术补充。

2. Mock / 测试环境切换

方式行为
下拉「Mock 本地」读本地 JSON；始终保留，与测试环境并列
下拉「测试环境」请求真接口；不可删除，随时可切回
切换下拉立即拉取当前数据源（无需先开定时刷新）
?mock=1仅默认选中 Mock；仍可在下拉切测试环境
无参数打开默认选中测试环境
改 symbol_idEnter 或失焦后按当前模式重新拉取
Mock 与测试环境两项始终同时存在；切换下拉后立即刷新。若用 file:// 打开，切测试环境可能因 CORS 失败，请用 ./start.sh 起 HTTP 服务。

3. Mock 文件命名

GET /debug/depthGather?symbol_id={id}

  → data/mock/depthGather.symbol-{symbol_id}.json
  → 回退 data/mock/depthGather.default.json

已内置示例：

  • 1000001 — BTC（18 档，每档 number 随机 0.01~10）
  • 1000003 — TRX

4. 响应结构 data

{
  "code": 0,
  "msg": "success",
  "data": {
    "stats": {
      "ask_price", "bid_price", "mark_price", "diff_price",
      "ask_qty", "bid_qty", "uid_num", "order_num"
    },
    "depth": {
      "ask": [{
        "price", "number", "uid_num", "order_num",
        "user_ids", "source_list", "direction"
      }],
      "bid": [ ... ]
    },
    "asks": [[price, cumQty], ...],
    "bids": [[price, cumQty], ...]
  }
}
页面读法：左侧订单簿与右侧纵向图均用 depth.ask/bid 的 number（每一档独立量，非累计）。 asks/bids 为接口原样累计数组，本页图表不使用。 修改 mock 后 HTTP 模式刷新即可；file:// 需重新运行生成 js/mock-data.js。

6. depthGather 用户 / 挂单字段

字段含义
uid_num该价位不同 UID 数量（表格 UV 列）
order_num该价位挂单笔数
user_ids该价位全部 UID，逗号分隔
number该价位标的量（表格 Qty）
source_list1=Web 2=App 3=量化 4=强平 5=关联
direction1 买盘 · -1 卖盘

页面内可展开「depthGather 接口 · 用户 / 挂单字段说明」查看完整说明。
